01 // TOKENIZATION & SUBWORD ENCODING

BPE / WordPiece

Tokenization breaks continuous raw text into discrete tokens. While simple whitespace or regex splits work for clean English, modern models rely on subword algorithms like Byte-Pair Encoding (BPE) and WordPiece. By iteratively merging frequent adjacent character pairs, they keep vocabulary sizes manageable while easily handling unseen words, typos, and technical abbreviations.

[ ALGORITHMIC WORKFLOW ]
1. Initialize character vocabulary with base symbols.
2. Count pairwise byte / character frequencies in corpus.
3. Merge the most frequent pair $(c_i, c_j) \rightarrow c_{new}$.
4. Repeat until target vocabulary threshold $V$ is satisfied.
[ APPLICATION IN COURSE PROJECT ]
Campus Connect utilizes specialized regex token patterns to preserve campus acronyms such as SJT, TT, MB, and course codes (e.g. CSE3002) as atomic tokens without fragmenting them.

02 // TEXT PREPROCESSING & MORPHOLOGY

Stemming vs Lemmatization

We explored how text normalization cleans input data for downstream tasks. We compared rule-based suffix truncation (Porter & Snowball Stemmers) against dictionary-backed morphological reduction (WordNet Lemmatizer). While stemming runs faster, lemmatization preserves actual dictionary roots and grammatical correctness, which proved critical when matching user queries.

[ COMPARATIVE ANALYSIS ]
• Stemming: Rapid, deterministic string truncation (e.g., "operating" → "oper"). High speed but risks over-stemming and non-lexical stems.
• Lemmatization: Morphological parse leveraging POS tags (e.g., "better" → "good"). Maintains valid dictionary lemmas for semantic precision.

03 // PART-OF-SPEECH (POS) TAGGING

HMM & Viterbi Decoding

Part-of-Speech tagging assigns grammatical categories (Noun, Verb, Adjective) to words in context. We worked with Hidden Markov Models (HMM) where words are observed emissions and grammatical tags are hidden states. We decoded the most likely tag sequence across a sentence using the dynamic programming Viterbi Algorithm in $O(T \times |S|^2)$ time complexity.

[ MATHEMATICAL FORMULATION ]
$$\hat{T} = \arg\max_T P(W|T) P(T) \approx \arg\max_T \prod_{i=1}^n P(w_i | t_i) P(t_i | t_{i-1})$$ Where $P(w_i|t_i)$ represents Emission Probability and $P(t_i|t_{i-1})$ represents Transition Probability derived from the Penn Treebank tagset.

04 // NAMED ENTITY RECOGNITION (NER)

IOB Chunking & Extraction

Named Entity Recognition detects and tags key information spans in text (names, locations, medical terms) using the standard BIO / IOB tagging scheme (Beginning, Inside, Outside). This was central to our Health Map session, where our pipeline extracted disease names, symptoms, and medical specialties directly from user query strings.

[ REAL-WORLD IMPLEMENTATION: HEALTH MAP ]
In our hands-on Health Map project, custom NER pipelines were configured to extract medical entities: [B-DISEASE: Acute Angina], [B-TREATMENT: Cardiac Catheterization], and [B-LOCATION: Katpadi Corridor].

05 // SYNTACTIC PARSING & DEPENDENCY GRAMMARS

CFG & CYK Algorithm

Parsing analyzes how words connect to form grammatical sentences. We worked with Context-Free Grammars (CFGs) normalized into Chomsky Normal Form (CNF) and decoded with the dynamic bottom-up CYK algorithm. We also explored Dependency Parsing, which directly links words through functional head-dependent grammatical relationships (nsubj, dobj, amod).

[ GRAMMATICAL FORM ]
CNF standard productions: $A \rightarrow B C$ or $A \rightarrow a$. Enables polynomial time syntactic tree verification and resolves structural ambiguity (e.g. PP-attachment dilemmas in natural English).

06 // LANGUAGE MODELS & VECTOR SEMANTICS

N-Grams to Self-Attention

We studied the transition from statistical word counting to dense semantic vector spaces: starting with N-Gram Markov Models with Laplace smoothing to prevent zero counts, moving into TF-IDF term weighting, and progressing to dense embeddings like Word2Vec and Transformer Self-Attention for measuring semantic similarity through cosine distance.

[ TF-IDF WEIGHTING ]
$\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \log\left(\frac{|D|}{1 + |\{d \in D : t \in d\}|}\right)$
Penalizes high-frequency terms while amplifying discriminative keywords.
[ COSINE SEMANTIC SIMILARITY ]
$$\text{Sim}(u, v) = \frac{u \cdot v}{\|u\| \|v\|}$$ Computes angular proximity between continuous semantic vectors for query retrieval.

TECHNICAL REFLECTIONS & REVIEW

Critical analysis of language models in institutional and clinical environments.
01 // REAL-WORLD UTILITY [HIGH VALUE]

Solving Everyday Campus & Healthcare Friction

Building both Campus Connect and Health Map showed me where NLP actually helps people in practice. In Campus Connect, new students get immediate answers to repetitive questions (curfews, leave rules, and block routes) without having to hunt through bulky PDF notices or wait in lines. In Health Map, patient triage is streamlined because people can describe their illness in their own words and still get routed to the right medical specialty and clinic.

02 // BOTTLENECKS [CHALLENGES]

Latency, Slang & Hallucination

1. Edge Latency: Running large transformer models locally on standard student laptops or low-cost CPU servers creates noticeable response delays.
2. Campus Slang & Acronyms: VIT students speak in acronyms ("SJT", "TT", "MB", "FFCS", "FAT exams", "Food Mall"). Standard pre-trained tokenizers split these into meaningless subwords unless handled with custom regex filters.
3. Hallucination Risk: For strict campus policies like hostel in-times or leave permissions, purely generative models can make things up. That's why pairing intent extraction with a deterministic state machine was much safer.

03 // FUTURE ROADMAP [NEXT GEN]

Quantized SLMs & Multilingual Support

1. Quantized Small Language Models: Fine-tuning a 4-bit quantized model (like Mistral-7B or LLaMA-3) on campus FAQs using LoRA so it can run quickly on consumer hardware.
2. Multilingual Support: Handling queries with code-mixing in Tamil, Telugu, and Hindi alongside English to help freshers from across India.
3. Live Campus Data: Integrating the navigation engine with real-time class timetables and campus shuttle schedules.

// COMPARATIVE ARCHITECTURAL AUDIT: STATE MACHINES VS GENERATIVE LLMS
Deterministic State Machines (Campus Connect Engine):
Zero factual hallucination, sub-millisecond response time, 100% deterministic compliance with hostel & academic rules, and native binding to Google Maps routing vectors.
Dense Semantic Vector Embeddings (Health Map Engine):
Overcomes lexical mismatch between informal patient symptoms and formal medical ontologies. Calculates cosine similarity over multidimensional embeddings to prioritize specialty triage.
